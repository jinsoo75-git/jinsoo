# 06. Extensions

> 본 문서는 `01-product.md`에 정의된 **확장 범위**를 다룬다. MVP(Phase 1~3, `04-tasks.md`)가 완료된 이후에만 착수하며, 여기 적힌 어떤 항목도 사용자 승인 없이 임의로 시작하지 않는다.

## 진행 규칙

- MVP 완료가 전제 조건이다. `04-tasks.md`의 Phase 1~3이 모두 완료 상태여야 착수 가능
- 각 확장 항목은 **착수 전 사용자 승인**을 받는다 (범위/일정 협의)
- 새 의존성이 필요한 항목은 `03-design.md`의 의존성 추가 정책(선택/대안/근거/트레이드오프 기록)을 먼저 따른다
- 항목 간 순서는 아래 표의 우선순위를 기본값으로 하되, 사용자가 순서를 재조정할 수 있다

## 확장 항목 개요

| # | 항목 | 목적 | 주요 의존성(예상) | 기존 설계 영향 |
|---|---|---|---|---|
| 1 | JWT 로그인 | 사용자 인증, 개인별 업무 구분의 전제 조건 | `python-jose` 또는 `pyjwt`, `passlib` | Task 모델에 `owner_id` 추가 필요 |
| 2 | 팀 | 다중 사용자가 업무를 공유/열람 | 위 인증 항목에 의존 | `Team`, `TeamMember` 모델 신설 |
| 3 | Kanban | 상태별 드래그앤드롭 시각화 | 프론트 드래그 라이브러리 또는 자체 구현 | 목록 UI를 보드 UI로 확장 (기존 카드 컴포넌트 재사용) |
| 4 | 채팅 | 팀 내 실시간 커뮤니케이션 | WebSocket 서버, 메시지 저장소 | `03-design.md` 5번 결정(폴링) 재검토 — 채팅은 폴링 부적합, WebSocket 전환 필요 |
| 5 | CI/CD | 자동 테스트/배포 파이프라인 | GitHub Actions 등 | 배포 대상 인프라 결정 필요 (미정) |

## 항목별 상세

### 1. JWT 로그인

- **목표**: 사용자별 로그인/인증. 이후 팀 기능의 전제 조건
- **범위 후보**: 회원가입, 로그인, 토큰 발급/검증, 인증이 필요한 엔드포인트 보호
- **결정 필요 사항**: 토큰 저장 위치(localStorage vs httpOnly 쿠키), 토큰 만료/갱신 정책
- **범위 외**: 소셜 로그인, 비밀번호 재설정 이메일 발송 (별도 협의 없이는 포함하지 않음)

### 2. 팀

- **목표**: 여러 사용자가 하나의 업무 보드를 공유
- **전제 조건**: JWT 로그인 완료
- **범위 후보**: 팀 생성/초대, 팀 단위 Task 조회, 팀원별 담당자 지정(`assignee_id`)

### 3. Kanban

- **목표**: `todo`/`in_progress`/`done` 상태를 컬럼으로 시각화하고 드래그로 상태 변경
- **범위 후보**: 3-컬럼 보드, 드래그앤드롭으로 `status` 변경 (기존 `PUT /api/tasks/:id` 재사용)
- **디자인 원칙**: `03-design.md`의 Mac OS 톤(rounded-xl, shadow-lg, backdrop-blur)을 컬럼/카드에도 동일 적용

### 4. 채팅

- **목표**: 팀원 간 실시간 메시지
- **주의**: `01-product.md` 범위 외 항목인 WebSocket이 이 시점에는 필요해짐 — 착수 전 `03-design.md` 5번 결정(폴링 vs WebSocket)을 갱신하고 근거를 기록한다
- **범위 후보**: 팀별 채널 1개, 메시지 발신/수신, 과거 메시지 조회

### 5. CI/CD

- **목표**: 커밋/PR 시 자동 테스트 실행, 배포 자동화
- **범위 후보**: GitHub Actions로 `pytest` 자동 실행 → 이후 배포 파이프라인은 배포 대상 확정 후 설계
- **전제 조건**: 배포 인프라(호스팅 방식) 결정

## 범위 외 (확장 단계에서도 다루지 않음)

`01-product.md`의 범위 외 항목(외부 결제, 네이티브 앱, WebRTC, 외부 캘린더, 파일 업로드)은 확장 단계에서도 그대로 범위 외로 유지한다. 별도 요청이 없는 한 포함하지 않는다.
